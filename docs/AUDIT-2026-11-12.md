# Audit: 12 November 2026

This pass continues PR #7 on `overnight/audit` (PR #8). It covers the Go app facade, cleanup, HTTP API, CLI, scanner and findings, background service, packaging, and React client. Fixes were limited to reproduced failures or concrete source paths with triggering inputs. The native Swift client is separate work on `feat/native-macos`.

The Go minimum is now `1.26.11`. On local Go `1.26.3`, govulncheck reported 25 reachable standard-library advisories and no third-party module findings. On `1.26.11`, it reports **No vulnerabilities found**. This is a toolchain advisory check, not a claim that every advisory was exploitable through ebb.

Staticcheck's remaining unused-field warning was a deliberate TypeScript-generator fixture. A narrow comment explains it; the field and its test remain. Raw bidirectional source text and the deprecated GOROOT test lookup were also corrected earlier in the audit.

## Safety checks

Tests cover root refusal, approval and expiry, scan boundaries, protected system/home/cloud folders, case and Unicode normalization, symlink spellings, replacement between planning and deletion, running-owner checks, Trash and undo, empty-Trash ordering, and MCP approval boundaries. Native Trash returns a filesystem path, matching Undo's input.

The deletion identity check compares device and inode. Editing an existing file's contents does not by itself replace its identity. README wording about refusing anything that “changed” should be read with this limitation; this audit did not silently add content hashing or change cleanup policy.

Hard links, APFS clones, sparse-file handling, symlink loops, unusual names and long paths were checked using temporary filesystem fixtures and existing scanner tests. Corrupted tree and truncated history input return errors. HTML escaping and spreadsheet formula escaping passed their existing hostile-name cases.

## Validation and limits

Consolidation checks passed: build, `make check`, full `go test -race -count=1 ./...`, staticcheck, govulncheck, UI typecheck and 70 Bun tests, plus all 20 browser e2e scenarios. The new opening-screen scenario was run before and after the fix. Final API and packaging results are recorded alongside their tests and in the PR description.

All mutating CLI/UI experiments used `EBB_SANDBOX=1` and a separate temporary `EBB_HOME`. The installed application, real launchd service, real configuration/state, and the other repository clone were left alone.

Remaining validation limits:

- Safari and the deployed hosted page were not manually exercised; browser e2e uses local Chrome.
- Real launchd upgrades and notification permission dialogs were inspected through source and fakes, without altering the installed service.
- APFS clone reclaimability after modifying a clone and every detector location across macOS 12 through 26 were not established.
- Simultaneous writes from independent CLI/server processes to configuration, notes, history indexes, or the two-file last-scan snapshot are not a cross-process transaction. Concrete source interleavings are recorded in the local audit notes; they were not reproduced in this pass and are not reported as confirmed defects.

This is a bounded audit with recorded coverage and limits, not a claim that every possible defect has been ruled out.
